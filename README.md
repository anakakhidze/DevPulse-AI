# DevPulse AI

DevPulse AI არის Python-ზე და LangGraph-ზე აგებული დეველოპერის ასისტენტი. ის მომხმარებლის ტექსტურ მოთხოვნას აანალიზებს, საჭიროებისამებრ აგროვებს GitHub-ის ან ვების მონაცემებს, ამზადებს შეჯამებას და ელფოსტით ან Slack-ით გაგზავნამდე აჩვენებს სრულ პრევიუს და ითხოვს მომხმარებლის თანხმობას.

ეს არის ლოკალურად გასაშვები ტერმინალის აპლიკაცია და არა საჯაროდ განთავსებული ვებ-სერვისი. LangGraph მართავს სამუშაო პროცესსა და მის მდგომარეობას; Gemini იღებს გადაწყვეტილებას, რომელი ინსტრუმენტი გამოიყენოს და როგორ შეაჯამოს მიღებული ფაქტები.

## შესაძლებლობები

- **GitHub:** ღია Issue-ების, ბოლო კომიტების, დამერჯილი Pull Request-ების და ცალკეული Pull Request-ის დეტალების მიღება.
- **ვებ-ძიება:** ტექნოლოგიური სიახლეების ძიება. თუ `.env`-ში `TAVILY_API_KEY` არის მითითებული, გამოიყენება Tavily Search. თუ გასაღები არ არის, კოდი ჯერ Google News RSS-ს მიმართავს, ხოლო Google News-ის მიუწვდომლობისას — Hacker News / Algolia-ს. ამიტომ Tavily აუცილებელი არ არის; ეს არჩევითი საძიებო სერვისია.
- **მომხმარებლის პარამეტრები:** `User ID`-ს უკავშირდება შენახული ელფოსტა, `owner/repo` ფორმატის რეპოზიტორია და ამოცნობილი ინტერესის თემები.
- **ელფოსტა:** Digest SMTP-ით იგზავნება. გაგზავნამდე ნაჩვენებია მიმღები, თემა და სრული ტექსტი; მომხმარებელი ადასტურებს `yes/no`-ით.
- **Slack:** შეტყობინება Incoming Webhook-ით იგზავნება არჩეულ არხზე. გაგზავნამდე ნაჩვენებია არხი და სრული ტექსტი; მომხმარებელი ადასტურებს `yes/no`-ით.
- **შეფასება:** `eval.py` ამოწმებს ინსტრუმენტების არჩევასა და იმას, ემყარება თუ არა Digest GitHub-ის მტკიცებულებებს LLM-as-a-Judge მიდგომით.

## საჭირო კომპონენტები

- Python 3.10 ან უფრო ახალი ვერსია.
- Gemini API key, რომლის მიღებაც შეიძლება [Google AI Studio-ში](https://aistudio.google.com/apikey). ის საჭიროა აგენტის ენობრივი მოდელისა და შეფასების სკრიპტისთვის.
- საჯარო GitHub რეპოზიტორიებისთვის GitHub token აუცილებელი არ არის. `GITHUB_TOKEN`-ის მითითება ზრდის GitHub API-ის მოთხოვნების ლიმიტს.
- Tavily key არჩევითია. მის გარეშე გამოიყენება ზემოთ აღწერილი უფასო საძიებო წყაროები.
- ელფოსტის გასაგზავნად საჭიროა SMTP-ის პარამეტრები. Gmail-ის ძირითადი პაროლის ნაცვლად გამოიყენეთ Google App Password.
- Slack-ზე გასაგზავნად საჭიროა Slack Incoming Webhook URL.

## საჭირო გამართვა

1. გადადით პროექტის საქაღალდეში და შექმენით ვირტუალური გარემო:

   ```powershell
   py -m venv venv
   .\venv\Scripts\Activate.ps1
   ```

2. დააყენეთ საჭირო ბიბლიოთეკები:

   ```powershell
   python -m pip install -r requirements.txt
   ```

3. პროექტის მთავარ საქაღალდეში შექმენით `.env` ფაილი და შეავსეთ საჭირო პარამეტრები. მაგალითად:

   ```env
   GOOGLE_API_KEY=YOUR_GEMINI_API_KEY
   GEMINI_MODEL=gemini-3.5-flash-lite
   GITHUB_TOKEN=
   TAVILY_API_KEY=

   SMTP_HOST=smtp.gmail.com
   SMTP_PORT=587
   SMTP_USE_SSL=false
   SMTP_USERNAME=
   SMTP_PASSWORD=
   SMTP_FROM=

   SLACK_WEBHOOK_URL=
   SLACK_CHANNEL_NAME=dev
   ```

   `GOOGLE_API_KEY` აუცილებელია. დანარჩენი ინტეგრაციების ველები მხოლოდ შესაბამისი სერვისის გამოყენებისას შეავსეთ. `.env`-ში საიდუმლო მნიშვნელობები ინახება, ამიტომ GitHub-ზე არ ატვირთოთ; `.gitignore` ამ ფაილს გამორიცხავს.

4. ელფოსტის გასაგზავნად შეავსეთ `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM` და SMTP სერვერის პარამეტრები. Gmail-ისთვის გამოიყენეთ Google App Password. `587` პორტი იყენებს STARTTLS-ს, ხოლო `465` — SSL-ს.

5. Slack-ის გასააქტიურებლად Slack App-ში ჩართეთ Incoming Webhooks, აირჩიეთ არხი და შექმენით webhook. მიღებული URL ჩაწერეთ `SLACK_WEBHOOK_URL`-ში. Webhook არჩეულ არხზეა მიბმული; `SLACK_CHANNEL_NAME` მხოლოდ დასტურის პრევიუში ნაჩვენები სახელია. URL საიდუმლოდ შეინახეთ.

## გაშვება

Windows PowerShell-ში გაუშვით:

```powershell
.\venv\Scripts\python.exe .\main.py
```

გაშვებისას პროგრამა გკითხავთ `User ID`-ს. ეს მომხმარებლის შენახული პარამეტრების გასარჩევი იდენტიფიკატორია და არა GitHub-ის მომხმარებლის სახელი. შემდეგ შეიყვანეთ მოთხოვნა, მაგალითად:

```text
   langchain-ai/langgraph რეპოზიტორიის main ბრენჩის ბოლო კომიტები და დამერჯილი PR-ები შეამოწმე და ქართულად შემაჯამე.
```

თუ შეჯამების გაგზავნა გსურთ, ეს ცალკე და მკაფიოდ მოითხოვეთ. აგენტი სრულ პრევიუს გაჩვენებთ; გასაგზავნად შეიყვანეთ `yes`, გასაუქმებლად — `no`. პროგრამის დასახურად შეიყვანეთ `exit`.

`agent.py` GitHub-ის MCP სერვერს Python MCP Client-ის მეშვეობით `stdio` რეჟიმში ავტომატურად უშვებს. ამიტომ ძირითადი პროგრამის გაშვებამდე `mcp_server.py`-ის ცალკე გაშვება საჭირო არ არის. სურვილის შემთხვევაში სერვერის დამოუკიდებლად გაშვება შეგიძლიათ ბრძანებით `python mcp_server.py`.

## სამუშაო ნაკადი და არქიტექტურა

`state.py`-ში აღწერილი `AgentState` აფართოებს LangGraph-ის `MessagesState`-ს და ინახავს შეტყობინებებს, მომხმარებლის იდენტიფიკატორსა და პარამეტრებს, გამოყენებულ ინსტრუმენტებს, გასაგზავნად გამზადებულ შეტყობინებას და დასტურის სტატუსს.

გრაფის ნაკადი:

```text
START → load_memory → agent
                         ├─ საჭიროა ინსტრუმენტი → tools → agent
                         ├─ ელფოსტა ან Slack მზადაა → human_approval → agent
                         └─ პირდაპირი პასუხი → save_memory → END
```

`load_memory` მომხმარებლის პარამეტრებს კითხულობს. `agent` კვანძში Gemini არჩევს, სჭირდება თუ არა GitHub-ის ან ვების ინსტრუმენტი. `tools` კვანძი აგროვებს მონაცემებს და პასუხებს მოდელს უბრუნებს. ელფოსტისა და Slack-ის ინსტრუმენტები შეტყობინებას მაშინვე არ აგზავნის: `human_approval` კვანძი `interrupt`-ით აჩერებს გრაფს და ტერმინალში მომხმარებლის გადაწყვეტილებას ელოდება. დასტურისას შეტყობინება იგზავნება, უარისას — უქმდება. ბოლოს `save_memory` მომხმარებლის პარამეტრებს ინახავს.

## GitHub MCP ინსტრუმენტები

`mcp_server.py` FastMCP-ს იყენებს GitHub API-ის ოპერაციების MCP ინსტრუმენტებად გამოსაქვეყნებლად:

- `get_github_repo_issues(repo_name)` — აბრუნებს მაქსიმუმ 10 ღია Issue-ს; Pull Request-ებს გამორიცხავს.
- `get_recent_commits(repo_name, branch="main")` — არჩეული ბრენჩის ბოლო 5 კომიტის SHA-ს, ავტორს, შეტყობინებას, თარიღსა და URL-ს აბრუნებს.
- `get_merged_pull_requests(repo_name)` — ახლახან განახლებული, დახურული PR-ებიდან მაქსიმუმ 5 დამერჯილს აბრუნებს.
- `get_pull_request_details(repo_name, pr_number)` — ერთი PR-ის სათაურს, აღწერას, სტატუსს, ბრენჩებს, ავტორსა და URL-ს აბრუნებს.

სერვერი მოთხოვნებს `api.github.com`-ს უგზავნის. თუ `GITHUB_TOKEN` მითითებულია, ის Bearer token-ად ემატება მოთხოვნას. ტოკენის გარეშეც შესაძლებელია საჯარო რეპოზიტორიების წაკითხვა, თუმცა მოქმედებს API-ის მოთხოვნების ლიმიტი.

## მეხსიერება და მდგომარეობა

- LangGraph-ის `InMemoryStore` მომხმარებლის პარამეტრებს მიმდინარე პროგრამის პროცესის მეხსიერებაში ინახავს.
- `devpulse_memory.sqlite3` პარამეტრებს `user_id`-ის მიხედვით ინახავს და შემდეგ გაშვებაზეც აღადგენს. ტექსტიდან ამოიცნობა ელფოსტა, `owner/repo` ფორმატის რეპოზიტორია და კოდში ჩამოთვლილი ინტერესების ზოგიერთი თემა.
- გრაფის `MemorySaver()` checkpointer საუბრის მიმდინარეობას მხოლოდ მიმდინარე პროცესის მეხსიერებაში ინახავს. პროგრამის დახურვის შემდეგ საუბრის სრული checkpoint-ები SQLite-ში არ ინახება.
- `devpulse_memory.sqlite3` და SQLite-ის WAL/SHM დამხმარე ფაილები `.gitignore`-შია მითითებული და რეპოზიტორიაში არ უნდა აიტვირთოს.

## შეფასების გაშვება

```powershell
.\venv\Scripts\python.exe .\eval.py
```

Tool Selection Accuracy ამოწმებს, ემთხვევა თუ არა მოდელის მიერ მაგალითის მოთხოვნაზე არჩეული ინსტრუმენტები მოსალოდნელ ინსტრუმენტებს. ამ შემოწმებისას ინსტრუმენტები მხოლოდ შერჩევისთვის ფასდება; GitHub-ს მოთხოვნა არ ეგზავნება და ელფოსტა ან Slack შეტყობინება არ იგზავნება.

Faithfulness შეფასების `faithfulness_judge(digest, github_evidence)` ფუნქცია GitHub-ის მტკიცებულებას ერთადერთ წყაროდ მიიჩნევს და Gemini-ს სთხოვს, შეამოწმოს, შეიცავს თუ არა Digest დაუდასტურებელ მტკიცებებს. შეფასების ნაკრები სამი ფიქსირებული მაგალითისგან შედგება. ეს LLM-ის შეფასებაა და ყველა შესაძლო გამოგონილ მტკიცებას აუცილებლად ვერ აღმოაჩენს.
